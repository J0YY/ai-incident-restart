Sequential Incident Review
DRAFT DESIGN / DEVELOPMENT MATERIALS / NO EMPIRICAL RESULTS / NOT PREREGISTERED

Question
Can a reviewer recognize when an earlier safety objection has been resolved while preserving warranted restrictions for other reasons? Does a focused decision record improve this judgment relative to a competent recovery checklist?

Scope and provenance
This design was prepared after seeing the original study and the completed Gemma reasoning rerun. It is a new prospective question, not a confirmatory rescue of the original claim. Three AI-authored development families exercise the software. They are excluded from any main bank, are not independent human validation, and cannot support an efficacy claim. No main-bank cases or human observations exist. A local hashed release is not an external preregistration.

Evidence sequence
At time 1, an actual defect justifies a restriction. At time 2, a new record does one of four things:
resolved: resolves O1 and establishes full-operation conditions.
failed: demonstrates the original problem remains.
new_concern: resolves O1 but establishes a different current problem O2.
missing: leaves O1's closure uncertain because a specified material record is absent.
The prospective policy already permits a new concern to block operation. The policy does not change between stages. All cases supply authority and a verified staging gate permitting LIMITED preparation. There are no valid HOLD answers in this deliberately bounded pilot. HOLD remains available to measure overrestriction. A separate future design is needed to study missing authority or failed staging gates.

Experimental factors
Two forms, three history presentations, two display orders, and four evidence branches, crossed within each family. One initial review per family/order/repetition is reused verbatim across all downstream forms, histories and branches. Initial review uses common neutral instructions, before treatment assignment. No initial answer is selected or excluded because it is correct, confident, invalid or agrees with the hypothesis. Repeated samples and sibling branches are not independent cases.
Form A: ordinary competent recovery checklist plus a generic review note.
Form B: the same competent checklist plus focused objection-disposition prompts.
Both forms expose exactly the same records and final-answer fields. Neither uses a primary label or ranks a record by its position. They share output capacity and numerical token caps. The intervention changes the focus of deliberation; it does not isolate a single cognitive mechanism or guarantee equal realized compute.
History fresh: a new conversation with the complete time-1 and time-2 evidence, without the earlier model answer.
History own: time-1 user packet, the actual earlier assistant final answer, then the time-2 packet and form.
History other: a new conversation with identical evidence and the same earlier answer quoted as another reviewer's note.
Own versus fresh bundles prior-answer exposure, role and context length. Own versus other keeps answer content but changes attribution and role formatting. Neither identifies psychological commitment. These are operational procedures, not claims about internal model states. Display order reverses the time-2 evidence entries while preserving timestamps and substantive facts.

Primary comparisons
Form B minus Form A within the own-history condition on (1) failure to grant warranted FULL on resolved cases and (2) unsupported FULL across the other three branches, equally weighted. Report all cells. Primary evaluation uses thinking enabled with the same 4096 total generated-token cap, including thought and answer, in every arm and stage. Report generated tokens and latency rather than claiming equal compute.
History comparisons, objection closure and new-concern detection are secondary. A benefit claim needs an improvement in one error direction without a material increase in the other, adequate decision coverage and an acceptable time cost. Benefit, harm and time margins require domain input before main collection. Null or adverse results are retained and reported. No extra arm, sample, token cap or case is added based on the effect direction.

Model and run plan
Pilot pinned Gemma model and revision match the completed reasoning rerun. Sampling .7 temperature, .9 top-p, top-k 0, BF16, SDPA, fixed batch size 4 and saved batch seeds. Development schedule has 3 families x 4 branches x 2 forms x 3 histories x 2 display orders x 1 repetition = 144 final assignments plus 6 initial assignments. Batches are shuffled within stages. All time-1 outputs are saved before constructing final prompts. No thought channel is replayed. If no final channel exists, use an explicit fixed missing-answer placeholder, retain the failure and mark it. Never present thought text as a final answer.
A main run requires a separately supplied bank, human validation records, selected models/revisions, justified fixed sample and precision plan, final margins, and a separate freeze. Development cases may not be promoted into the main bank. This implementation intentionally permits development release creation only; main freezing is not yet enabled. It is better to block an unvalidated main run than to manufacture an independent bank with the same author.

Preservation and stopping
Freeze code, prompts, cases, hidden keys, config and assignments before inference. Runtime verifies the hashes and exact schedule. Save every raw response, final answer, token IDs, input messages/hash, generation settings and elapsed time. One outcome per assigned stage; no repair prompt for malformed answers. A stopped batch may be resumed only if no committed output exists; partial uncommitted generation cannot be recovered and must be documented. Completed batch bytes must remain unchanged. A separately saved hash receipt is checked on every resume and analysis; missing or mismatched receipts stop the run for investigation. Hold an exclusive process lock on the output directory. Preserve separate environment and interruption records. Stop on infrastructure errors; never change protocol or silently overwrite an attempt. Completion requires every assignment exactly once.

Human comparison
The companion human_extension.txt adapts the prior unrun human-study draft to this evidence sequence. Human research is a separate trial, not a model simulation. Enrollment, qualifications, consent, institutional determination, compensation and secure storage require real responsible people. None have been supplied or performed by this package.
